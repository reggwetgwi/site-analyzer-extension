# Site Analyzer — расширение для отдела продаж

> **EN:** Chrome/Edge extension (Manifest V3) for sales reps doing cold outreach.
> Open a prospect's website, click the icon — the extension audits the page DOM
> against 15+ SEO and commercial signals, sends the summary to an LLM and returns
> a personalized call opener, which services to pitch (and which not to) with
> reasons, plus a technical breakdown. No backend required.

Браузерное расширение для менеджеров по продажам. Открываешь сайт потенциального
клиента, жмёшь на иконку — получаешь разбор сайта и готовую фразу для холодного звонка.

## Зачем

Перед звонком менеджер должен что-то знать о сайте клиента — иначе разговор
начинается с «мы предлагаем услуги продвижения», и на этом заканчивается.
Ручной разбор одного сайта занимает 10–15 минут, а в обзвоне их сотня.
Расширение сжимает это до одного клика и даёт менеджеру конкретику:
не «у вас проблемы с SEO», а «у вас на главной нет заголовка H1, а в поиске
по вашему запросу вы на второй странице».

## Что выдаёт

1. **Открывашка для звонка** — 1–2 персонализированные фразы с конкретной
   проблемой сайта
2. **Что предлагать** — услуги с пометкой приоритета и обоснованием
3. **Что НЕ предлагать** — с причиной (например, не продавать контекст сайту
   без коммерческих страниц)
4. **Сильные и слабые стороны** сайта
5. **Техническая сводка** — сворачиваемый блок с сырыми данными

## Что анализируется

Всё снимается со страницы через DOM, без внешних сервисов:

`title` · `meta description` · `H1`/`H2` · HTTPS · viewport (мобильная адаптация) ·
счётчики аналитики (GA, Яндекс.Метрика) · разметка Schema.org · `canonical` ·
изображения без `alt` · формы · телефон и CTA-кнопки · отзывы и рейтинги ·
онлайн-чат · ссылки на соцсети · коммерческие сигналы (цены, каталог, корзина) ·
`robots meta` (noindex)

Собранный срез уходит в LLM одним запросом, ответ приходит структурированным JSON
и рендерится в попапе.

## Технические решения

- **Manifest V3**, без background-страницы и без бэкенда — расширение самодостаточно
- скрипт анализа инжектируется через `chrome.scripting.executeScript` и не имеет
  внешних зависимостей: он целиком сериализуется в страницу
- API-ключ хранится в `chrome.storage.local`, вводится на отдельной странице настроек
- обработаны краевые случаи: системные страницы `edge://` и `chrome://`,
  неверный ключ, превышение лимита запросов
- кнопка «Скопировать открывашку» кладёт текст сразу в буфер обмена

## Установка

1. Открыть `chrome://extensions` (или `edge://extensions`)
2. Включить «Режим разработчика»
3. «Загрузить распакованное расширение» → указать папку с проектом
4. Нажать на иконку → «Настройки» → вставить API-ключ

## Настройка под свои услуги

Расширение не привязано к конкретному набору услуг. Каталог задаётся константой
`SERVICES` в начале `popup.js` — название, иконка и цвет каждой услуги, — а рядом
в `SERVICES_BRIEF` описывается, что в услугу входит и кому её уместно предлагать.
Именно это описание уходит в модель и определяет её рекомендации. В репозитории
лежат нейтральные заглушки: замените их своими до первого запуска.

Ключ Gemini берётся в Google AI Studio, у бесплатного тарифа хватает лимитов
для повседневного обзвона.

## Структура

| Файл | Назначение |
|---|---|
| `manifest.json` | манифест V3, разрешения `activeTab` / `scripting` / `storage` |
| `popup.html`, `popup.js` | интерфейс, сбор DOM, запрос к модели, рендер результата |
| `settings.html`, `settings.js` | страница настроек и хранение ключа |
| `styles.css` | тёмная тема попапа шириной 400 px |
| `generate_icons.py` | генерация набора иконок из логотипа |
